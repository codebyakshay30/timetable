## Reflection

Skills, plugins, MCP, and Git worktrees address four distinct layers of an AI-agent toolchain, and Git worktrees solve a fundamentally different problem from the other three. A Skill packages procedural domain knowledge and anti-fabrication rules—teaching the agent how to query `timetable.csv` and refuse guessed classes. A plugin is a packaging and distribution unit, bundling Skills, slash commands, lifecycle hooks, and MCP configurations into one installable artifact (`campus-helpdesk`). MCP standardizes runtime integration with external data and systems, giving the agent typed, schema-validated tools (`get_timetable`, `get_fee_status`) and read-only resources (`hostel://rules`). Worktrees, by contrast, say nothing about agent knowledge, distribution, or external tools; they solve a version-control isolation problem by giving parallel coding sessions separate working directories, indexes, and `HEAD` pointers over one shared Git object store.

I would choose a Skill over an MCP tool when the workflow consists mainly of instructions, formatting conventions, or judgement over small, static, non-sensitive local reference files—such as explaining CSV column meanings or structuring a timetable table. An MCP tool is the right choice whenever data is live, sensitive, or shared across systems, requires authentication, or demands strict programmatic input validation. In Part B, `SKILL.md` rules discouraged guessing, yet prompt instructions remain advisory; only the MCP server's regex and schema checks in `campus_data.py` can deterministically reject malformed inputs like `"1002; DROP TABLE"` with `isError: true`.

I would never delegate without human review any action with irreversible or security-critical consequences: resolving Git merge conflicts (where syntactically valid edits can silently drop a security check), modifying `PreToolUse` hooks or permission policies, installing third-party plugins or MCP servers whose tool descriptions execute as prompt text, mutating real student or fee records, or running destructive Git commands such as force-pushes and forced worktree removals. Across every part of this assignment, treating AI output as untrusted until verified against primary specifications and live terminal runs prevented fabricated claims, broken paths, and silent failures.
